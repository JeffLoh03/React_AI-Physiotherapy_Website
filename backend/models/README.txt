re+active model directory
=========================

The backend loads its MediaPipe pose model, trained exercise classifier, class
labels, and exact feature order from this directory during startup.

Required runtime files
----------------------

1. pose_landmarker_lite.task
   MediaPipe Pose Landmarker model used to detect 33 body landmarks.

2. exercise_classifier_best.pkl
   Trusted scikit-learn classifier used to identify Ex1 through Ex6.
   It is published separately as the model-v1 GitHub release asset. Download it
   before starting the backend:

   https://github.com/JeffLoh03/AI-Physiotherapy_Website/releases/download/model-v1/exercise_classifier_best.pkl

3. exercise_names.json
   Maps classifier labels to display names:
   Ex1 = Shoulder Abduction
   Ex2 = Shoulder V-W Exercise
   Ex3 = Inclined Push-Up
   Ex4 = Hip Abduction
   Ex5 = Forward Lunge
   Ex6 = Squat

4. feature_order.json
   The exact ordered feature list expected by the classifier. At startup,
   main.py verifies that this list matches the 132 features generated by
   pose_features.py.

Optional development file
-------------------------

all_features.csv
   Training/export data retained for model investigation. It is not loaded by
   the running FastAPI application and is not required for normal inference.

Expected layout
---------------

backend/models/
|-- README.txt
|-- pose_landmarker_lite.task
|-- exercise_classifier_best.pkl
|-- exercise_names.json
|-- feature_order.json
`-- all_features.csv              (optional)

Important rules
---------------

- Do not rename the required files unless the paths in backend/main.py are also
  updated.
- Do not edit feature_order.json manually. Export it from the same training
  pipeline that produced the classifier.
- A matching feature count is not enough; names and order must both match.
- Only load a .pkl/joblib file that you created or trust. Deserializing an
  untrusted model file can execute malicious code.
- exercise_classifier_best.pkl is larger than GitHub's normal 100 MiB file
  limit and is intentionally excluded from Git history. This repository
  publishes it as the model-v1 GitHub release asset.

Startup checks
--------------

From the repository root:

    cd backend
    python -c "from pose_features import FULL_WINDOW_FEATURE_NAMES; print('Generated features:', len(FULL_WINDOW_FEATURE_NAMES))"

The command should report 132 generated features. A full backend startup
additionally loads every required model file:

    uvicorn main:app --host 0.0.0.0 --port 8000

If startup reports a missing model or feature-order mismatch, verify the files
above before changing pose_features.py.
